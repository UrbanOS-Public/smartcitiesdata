# Reaper 3.0.8 OTP25 Kubernetes Startup Fixes

**Date:** 2025-12-11
**Version:** Reaper 3.0.8
**Branch:** otp25
**Environment:** Kubernetes (mdot-ride-dev-ns)

## Summary

This document details all changes required to successfully deploy and start Reaper 3.0.8 on OTP25 in a Kubernetes environment. The deployment went through multiple iterations (3.0.3 → 3.0.8) to resolve critical issues related to process group (:pg) availability, Redis configuration, and Kafka event processing.

## Critical Issues Resolved

### 1. Process Group (:pg) Server Not Running

**Problem:**
- Brook.Server requires the :pg (process groups) GenServer to be running
- OTP23+ includes :pg as a module in the kernel application, not as a separate application
- The :pg server process was not automatically started, causing Brook initialization to fail with `{:noproc, {:gen_server, :call, [:pg, {:join_local, ...}]}}`

**Solution:**
Explicitly start the :pg server in `apps/reaper/lib/reaper/application.ex`:

```elixir
def start(_type, _args) do
  Logger.info("======================================================")
  Logger.info("Reaper.Application starting...")
  Logger.info("======================================================")

  # Verify :pg module is available (part of kernel application in OTP 23+)
  if Code.ensure_loaded?(:pg) do
    Logger.info("Process group (:pg) module is available and loaded")

    # Ensure the :pg server process is running
    case Process.whereis(:pg) do
      nil ->
        Logger.warning("Process group (:pg) server is NOT running, attempting to start it...")
        case :pg.start_link() do
          {:ok, pid} ->
            Logger.info("Successfully started :pg server (pid: #{inspect(pid)})")
          {:error, {:already_started, pid}} ->
            Logger.info(":pg server already started (pid: #{inspect(pid)})")
          {:error, reason} ->
            Logger.error("CRITICAL: Failed to start :pg server: #{inspect(reason)}")
        end
      pid ->
        Logger.info("Process group (:pg) server is running (pid: #{inspect(pid)})")
    end
  else
    Logger.error("CRITICAL: Process group (:pg) module is NOT available!")
  end

  # ... rest of supervision tree
end
```

**IMPORTANT:** Do NOT add `:pg` to `extra_applications` - it is part of the kernel application and will cause test failures with `{:pg, {'no such file or directory', 'pg.app'}}`.

### 2. Quantum Scheduler Redis Configuration Empty

**Problem:**
- `Reaper.Quantum.Storage.Connection` was receiving empty configuration `[]`
- This caused Redis connection failures: `%Redix.ConnectionError{reason: :econnrefused}`
- Logs showed: `Attempting to start Quantum storage (Redis) with config: []`

**Root Cause:**
Configuration was incorrectly placed in `apps/reaper/runtime.exs`, which is NOT used in Elixir releases. Releases use the ROOT `config/runtime.exs` file.

**Solution:**
Added Quantum.Storage configuration to `config/runtime.exs` (ROOT level):

```elixir
# Configure Reaper Quantum Scheduler storage (Redis)
config :reaper, Reaper.Scheduler,
  storage: Reaper.Quantum.Storage,
  global: true,
  overlap: false

config :reaper, Reaper.Quantum.Storage, redix_args
```

**Files Involved:**
- ✅ `config/runtime.exs` - ROOT runtime config (USED in releases)
- ❌ `apps/reaper/runtime.exs` - App-specific runtime (NOT used in releases)

### 3. Enhanced Diagnostic Logging

Added comprehensive logging throughout the startup sequence to aid in troubleshooting:

**In `apps/reaper/lib/reaper/application.ex`:**

```elixir
defp redis() do
  redix_config = Application.get_env(:redix, :args, [])

  case redix_config do
    nil ->
      Logger.info("Redis: No configuration found, Redis will not be started")
      []
    redix_args ->
      full_args = Keyword.put(redix_args, :name, redis_client())
      Logger.info("Redis: Starting with config: #{inspect(full_args)}")
      {Redix, full_args}
  end
end
```

**In `apps/reaper/lib/reaper/migrations.ex`:**

```elixir
def init(_args) do
  Logger.info("======================================================")
  Logger.info("Reaper.Migrations starting...")
  Logger.info("======================================================")

  # Verify :pg module is available
  if Code.ensure_loaded?(:pg) do
    Logger.info("Reaper.Migrations: :pg module is available and loaded")
    case Process.whereis(:pg) do
      nil ->
        Logger.error("Reaper.Migrations: CRITICAL - :pg server is NOT running!")
      pid ->
        Logger.info("Reaper.Migrations: :pg server confirmed running (pid: #{inspect(pid)})")
    end
  else
    Logger.error("Reaper.Migrations: CRITICAL - :pg module is NOT available!")
  end

  # ... Brook startup ...

  # Enhanced Redis error logging
  case start_quantum_storage() do
    {:ok, quantum} ->
      Logger.info("Reaper.Migrations: Quantum storage connected successfully")
      migrate_quantum_task()
      stop_quantum_storage(quantum)

    {:error, %Redix.ConnectionError{reason: reason} = error} ->
      redis_config = Application.get_env(:reaper, Reaper.Quantum.Storage, [])
      Logger.warning("======================================================")
      Logger.warning("Reaper.Migrations: Redis connection FAILED")
      Logger.warning("  Error reason: #{reason}")
      Logger.warning("  Redis config: #{inspect(redis_config)}")
      Logger.warning("  Full error: #{inspect(error)}")
      Logger.warning("  Skipping Quantum migrations - scheduled jobs will not be migrated")
      Logger.warning("======================================================")
  end
end

defp start_quantum_storage() do
  config = Application.get_env(:reaper, Reaper.Quantum.Storage, [])
  Logger.info("Reaper.Migrations: Attempting to start Quantum storage (Redis) with config: #{inspect(config)}")
  Reaper.Quantum.Storage.Connection.start_link(config)
end
```

### 5. Test Fixes

**Problem 1: Auth Retriever Error Handling**
Tests expected specific error messages but `reraise` was changing the error format.

**Solution in `apps/reaper/lib/reaper/auth_retriever.ex`:**

```elixir
defp handle_content_encoding(body, "gzip") do
  try do
    :zlib.gunzip(body)
  rescue
    _ ->
      raise "Unable to decompress auth credentials. Payload may be corrupted or not compressed."
  end
end

defp handle_content_encoding(body, encoding) do
  raise "Unsupported content encoding: #{encoding}. Only 'gzip' is supported."
end
```

**Problem 2: Tzdata Not Initialized in Tests**
Time delta calculations failed with `{:error, :time_zone_not_found}` in test environment.

**Solution in `apps/reaper/test/unit/test_helper.exs`:**

```elixir
# Ensure tzdata is started for DateTime operations in tests
{:ok, _} = Application.ensure_all_started(:tzdata)

# Give tzdata a moment to fully initialize
Process.sleep(100)

# Force tzdata to initialize its ETS tables by making queries
try do
  Tzdata.zone_exists?("America/New_York")
  Tzdata.zone_exists?("Etc/UTC")
  Tzdata.TimeZoneDatabase.time_zone_periods_from_wall_datetime(~N[2020-01-01 00:00:00], "Etc/UTC")
rescue
  error ->
    IO.puts("Warning: tzdata initialization failed: #{inspect(error)}")
end

ExUnit.start()
```

## Runtime Configuration Best Practices

### Development vs Production Configuration

1. **Development:** Uses `config/*.exs` files (config.exs, dev.exs, test.exs)
2. **Production (Releases):** Uses `config/runtime.exs` (ROOT level)

**Key Insight:**
- `apps/<app>/runtime.exs` files are NOT loaded in releases
- All release configuration must be in `config/runtime.exs`

### Proper Runtime Config Structure

```elixir
# config/runtime.exs
import Config

if config_env() == :prod do
  # Common configuration
  redix_args = [
    host: redis_host,
    port: redis_port,
    password: redis_password  # if set
  ]

  # Service-specific configuration
  config :reaper, Reaper.Scheduler,
    storage: Reaper.Quantum.Storage,
    global: true,
    overlap: false

  # Storage backend configuration
  config :reaper, Reaper.Quantum.Storage, redix_args
end
```

### Common Startup Issues

#### Issue: `:pg` server not running
**Symptoms:**
```
{:noproc, {:gen_server, :call, [:pg, {:join_local, :reaper_brook, ...}]}}
```
**Solution:** Ensure :pg.start_link() code is present in application.ex

#### Issue: Empty Redis configuration
**Symptoms:**
```
[info] Reaper.Migrations: Attempting to start Quantum storage (Redis) with config: []
[error] %Redix.ConnectionError{reason: :econnrefused}
```
**Solution:** Ensure Quantum.Storage config is in ROOT config/runtime.exs

#### Issue: Brook deserialization errors
**Symptoms:**
```
expected Brook.Event.__struct__/1 to return a map with a :__struct__ key that holds the name of the struct (atom), got: %{__struct__: "Elixir.SmartCity.Ingestion", ...}
```
**Solution:** Reset Kafka consumer group offset to skip old incompatible events:

```bash
# 1. Scale down deployment
kubectl scale deployment reaper --replicas=0 -n mdot-ride-dev-ns

# 2. Reset offset to latest
kafka-consumer-groups --bootstrap-server pipeline-kafka-bootstrap:9092 \
  --group reaper-events \
  --reset-offsets --to-latest \
  --topic event-stream \
  --execute

# 3. Scale back up
kubectl scale deployment reaper --replicas=1 -n mdot-ride-dev-ns
```

## Lessons Learned

1. **:pg is NOT an application** - it's a module in the kernel application, do not add to extra_applications
2. **Elixir releases use config/runtime.exs** - NOT apps/*/runtime.exs files
3. **Always add diagnostic logging** - Critical for troubleshooting production issues
4. **Test in Kubernetes** - Local development may not reveal all deployment issues
5. **Kafka offset management** - Consumer groups must be inactive to reset offsets
